# Media Guide — uploading videos & regenerating assets

## Folder contract (project root)

| Folder | Role | Rule |
| --- | --- | --- |
| `media/reference_videos/` | Previously approved clips (reference archive) | Never modified |
| `media/videos_to_upload/` | **Upload inbox for new clips** | Drop new files here |
| `media/processed/` | Metadata + manifests generated by the pipeline | Safe to regenerate |
| `media/thumbnails/` | Contact sheets for visual inspection | Safe to regenerate |
| `media/brand/` | Official logo (supplied master) | Never modified |
| `public/media/` | Web-served derivatives (frames/video/posters/logo) | Generated output |

## How to add the new HTE75 video (or any replacement clip)

1. Copy your new clip into `media/videos_to_upload/` (MP4 / H.264 / 16:9 preferred,
   but the pipeline inspects and adapts to whatever you give it).
2. Open `scripts/media_pipeline.sh` and point `HERO_SRC` (or `REF_IN`/`NEW_IN`) to
   your new file — the current default picks the upload-inbox clip automatically.
3. Run the pipeline:

   ```bash
   bash scripts/media_pipeline.sh
   ```

   It will: probe the file with `ffprobe` → regenerate the 120-frame scrub sequence
   (desktop 640×384 + mobile 416×250 WebP) → rebuild the watermark-free MP4 →
   refresh posters/OG image → rebuild contact sheets → update
   `media/processed/frame_manifest.json`.
4. Restart/reload the dev server; the site picks up `public/media` automatically.
5. Review `media/thumbnails/contact_sheet_sequence.jpg` and update the chapter time
   windows in `src/lib/shotMap.ts` if your new footage has different camera moves.
   The chapter table is documented in `docs/SHOT_MAP.md`.

Originals are never touched: the pipeline only reads from `media/` and writes to
`media/processed`, `media/thumbnails` and `public/media`.

## Logo

`media/brand/parto_plastic_logo.jpg` is the official master. Derivatives
(`public/media/brand/parto_logo_transparent*.png`, `public/favicon.png`) are
background-removed copies generated by `scripts/process_logo.py` — rerun it after
replacing the master:

```bash
python3 scripts/process_logo.py
```

The artwork itself is never redrawn or recolored.

## Frames vs native video — how the site decides

- **Scrub hero**: WebP frame sequence on `<canvas>` (deterministic, reversible,
  no codec seek latency). This is the primary renderer.
- **Gallery dialog**: native `<video muted playsInline controls loop>` — used where
  linear playback is wanted (user-gesture initiated, so autoplay policies apply cleanly).
- **Fallbacks**: poster image if the sequence fails to load; static layout under
  reduced motion.

This split is recorded in `docs/prd/appendices/DECISION_LOG.md`.
