# Repository and Handoff Standard

Keep source, docs, tests and public assets organized. Do not commit build output unless hosting requires it, caches, local databases, `.env`, credentials, browser profiles or temporary downloads. Keep lockfiles for reproducible installs and asset licensing notes.

Documentation minimum: README setup/dev/build/test, architecture decisions, asset manifest, support configuration, test results, known limitations/missing inputs, and deployment notes for the actual host.

Use factual handoff statuses: Implemented and verified; Implemented but not verified; Blocked by missing input; Not implemented. Never summarize these as “done” without qualification.
